## What you get

The market's metadata **plus** the single snapshot whose `time` is
closest to `{timestamp}`. The timestamp is passed as either a
millisecond epoch or an ISO-8601 string. The embedded `gap_ms` tells
you exactly how stale the match is.

If no snapshot falls within `tolerance_ms` of the requested time, the
response is `404` with `error.code = SNAPSHOT_NOT_FOUND` and
`details.nearest_gap_ms` for diagnosis.

<Info>
Free keys can query point-in-time snapshots only for the newest 50
markets in the requested `(coin, type)` pair. Older known markets
return `403` with `error.code = PLAN_UPGRADE_REQUIRED`.
</Info>

    "series_ticker": "KXBTC15M",

## Fields

The `data` object is the full
[Market](/api-reference/v1/get-market) record (same fields as Get
Market) plus a `snapshot` key. The snapshot itself adds one extra
field on top of the standard [snapshot
shape](/api-reference/v1/list-snapshots#snapshot-fields):

- `gap_ms` - milliseconds between the requested `timestamp` and the
  returned snapshot's `time`. Always less than `tolerance_ms` on a
  successful response.

`orderbook_yes` / `orderbook_no` are returned only when
`?include_orderbook=true`.

<Tip>
Use this to line a backtest decision up to a wall-clock moment without
scanning the whole snapshot window. Snapshots are recorded at ~100 ms
cadence, so the default `tolerance_ms=2000` is almost always the right
value - tighten it if you need stricter matches and are happy to
accept more `SNAPSHOT_NOT_FOUND` responses.
</Tip>
